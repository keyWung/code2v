# 代码画物理 EP07：圆周运动

Remotion + React + TypeScript，竖屏 1080x1920 / 30fps / 60 秒（1800 帧，6 镜）。

- 数据唯一来源：`episodes/ep07-yuanzhou.json`
- 配色唯一来源：`src/theme.ts`，色值与 EP01 完全一致（`npm run verify` 会比对）
- ω、a 都由 JSON 里那两行代码现算：`const omega = v / r;` `const a = v * v / r;`（`src/physics.ts` 的 `omegaOf()`、`accelOf()`，`verify` 会拿 JSON 原句逐点比对）；T = 2πr / v
- 运动按真实时间：小球每帧转 ω / 30 弧度，r = 2 m 一圈 3.14 秒，r = 1 m 一圈 1.57 秒；两个圆每帧走的弧长一样（线速度相同）
- 画面比例：1 米 = 130 像素；速度箭头 30 像素每 m/s（两个圆都是 120 像素）；向心加速度箭头 7.5 像素每 m/s²（8 → 60 像素，16 → 120 像素）
- 镜 5 四格：汽车摩擦力、绳子拉力、圆锥摆合力都只用黄色箭头标“指向圆心的合力”；圆锥摆的重力和拉力画成细紫线，合力 = 两者矢量和，水平指向转轴

## 和规划的几处不同

- **镜 5 多了第 4 格“力不够时”**：对应口播最后一句。绳一断，小球沿断开那一刻的切线走直线，频闪残影间隔相等，写“按惯性走直线，不是被推出去的”。全片不出现“离心力”三个字（`verify` 会查）。
- **圆锥摆画成某一瞬间的侧视受力图**：摆球停在轨迹最右点，这样重力、拉力、合力都在画面平面里、长度不被透视压缩；汽车和绳拉小球两格是俯视，物体一直在转。
- 四格里的转速是示意（0.9 rad/s），不按 4 m/s 的比例；镜 1-4 的两个圆才是按比例的。
- 口播按全片统一语速（云希 ×1.18）全部放得下，没有改 JSON。

## 常用命令

```bash
npm run studio   # 浏览器里预览、拖时间轴（带口播）
npm run verify   # 自查清单：两组数字、代码来源、方向与垂直、四格受力、离心力说法、分镜帧、盖章、章节进度、遮挡区、颜色来源
npm run vo       # 重新生成 public/vo/*.wav（默认微软「云希」男声，全片统一 1.18 倍速）
npm run dub      # 只换配音：口播合进无配音版画面，几秒完成
npm run stills   # 渲染关键帧到 out/frames/，加 --safe 叠加平台遮挡区
npm run render   # 重渲画面：成片、无配音版、封面、字幕全部输出到 out/
```

## 沿用前几期踩过的坑

- **冻结段闪烁**：弹簧动画 40 帧后定格为精确的 1（`settle`），不动画字号；列表 key 一律用唯一编号；`render` 每次都逐字节比对 1650–1799 帧，不一致就停下、不出片。
- **语速前后不一**：`vo` 只用一个语速，按最后一个字说完的时间判断放不放得下；放不下就报错，请精简 JSON 口播。
- **macOS 13 跑不了 Remotion 自带 ffmpeg**：`render` 先出 JPEG 序列，再用 `ffmpeg-static` 编码和混音。
- **edge-tts 不走系统代理**：脚本显式传 `HTTPS_PROXY`，断线自动重试；口播文字会发到微软服务器。
- **渲染用的 Chrome 下载很慢**：已放在 `node_modules/.remotion/`（从 EP05 克隆）。重装依赖后若卡住，见 EP02 README 的手动下载步骤。
- **字幕分行符和公式撞了**：以前用“ / ”分两行，这期公式 `a = v² / r` 里也有“ / ”。现在只在“。/”处分行，`verify` 检查镜 3 字幕是一整行。
- **跟着物体跑的标签**：镜 1 之后速度箭头只标一个“v”，4 m/s 写在常驻小标签和运行结果里；`verify` 逐帧检查箭头和标签不出画面、不压小标签、代码区和遮挡区。
- **箭头比例**：同一个 A_PX 下，大圆的 a 箭头只有半径的 1/4 多，小圆的接近半径；这是真实比例，不单独放大，`verify` 检查小圆箭头不越过圆心。
- **遮挡区**：两个圆、四格、所有箭头都在右侧互动栏（x≥920 且 y≥900）和底部操作栏（y≥1540）之外。
- **封面裁切**：9:16 封面的内容放在中间 1440 高的区域，主页裁成 3:4 时不会被切掉。
